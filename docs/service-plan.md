# 🍽️ 「오늘 뭐 먹지 AI」 서비스 기획서

## 1. 서비스 개요

### 서비스명
**오늘 뭐 먹지 AI**

### 한 줄 소개
> 메뉴 하나가 아니라, 오늘 먹고 싶은 한 상을 골라드립니다.

### 서비스 목적
매일 반복되는 “오늘 뭐 먹지?”라는 고민을 줄이기 위해 사용자의 식사 상황과 취향을 입력받고, AI가 조건을 분석하여 서로 어울리는 메뉴로 구성된 **3가지 한 상 차림**을 추천하는 웹서비스를 제작한다.

---

## 2. 문제 정의

일반적인 메뉴 추천 서비스는 음식 하나를 무작위로 추천하거나 단순 메뉴 목록을 보여주는 경우가 많다.

그러나 실제 식사에서는 메인요리 하나만 결정하는 것이 아니라 국물, 반찬, 안주 등 함께 먹을 음식까지 고민하게 된다.

따라서 본 서비스는 단일 메뉴가 아니라 **서로 어울리는 여러 메뉴를 하나의 한 상으로 구성하여 추천하는 것**을 핵심 차별점으로 설정하였다.

---

## 3. 주요 사용자

다음과 같은 사용자를 주요 대상으로 한다.

- 오늘 먹을 메뉴를 결정하기 어려운 사용자
- 가족이나 친구와 함께 먹을 메뉴를 고민하는 사용자
- 원하는 맛과 조리시간에 맞는 식사를 찾는 사용자
- 보유한 식재료를 활용하고 싶은 사용자
- 술과 함께 먹기 좋은 메뉴 조합을 찾는 사용자

---

## 4. 핵심 차별점

### 일반적인 메뉴 추천

```text
오늘의 추천 메뉴
→ 제육볶음
```

### 오늘 뭐 먹지 AI

```text
PICK 1. 매콤한 집밥 한 상

🍴 제육볶음
🍴 된장찌개
🍴 계란말이

술 궁합: ★★★★☆
조리 부담: 보통
맛: 매콤 · 구수 · 담백

추천 이유:
서로 잘 어울리는 음식으로 구성된 한 상입니다.
```

즉, 메뉴 하나가 아니라 **실제로 함께 먹을 수 있는 식사 조합**을 추천한다.

## 5. 페이지 구성

서비스는 최소 3개의 주요 페이지로 구성하였다.

### 5.1 HOME

서비스의 첫 화면이다.

주요 내용:

- 서비스명
- 서비스 핵심 메시지
- 주요 기능 소개
- AI 메뉴 추천 페이지 이동
- 메뉴 추천 / ABOUT 내비게이션

### 5.2 메뉴 추천

서비스의 핵심 기능을 제공하는 페이지이다.

사용자가 식사 조건을 입력하고 AI에게 추천을 요청한다.

AI는 입력 조건을 분석하여 **3개의 서로 다른 한 상**을 생성한다.

각 PICK에는 최소 3개의 음식이 포함된다.

### 5.3 ABOUT

서비스의 목적과 작동 방식을 설명한다.

주요 내용:

- 서비스를 만든 이유
- 기존 메뉴 추천과의 차이
- AI 추천 방식
- 주요 기능
- 레시피 검색 기능
- 메뉴 추천 페이지 이동

## 6. 사용자 입력 정보

AI 추천을 위해 다음 정보를 입력받는다.

| 항목 | 내용 |
|---|---|
| 함께 먹는 사람 | 혼자, 가족, 친구 등 |
| 식사 상황 | 일반 식사, 특별한 식사 등 |
| 음식 종류 | 원하는 음식 종류 |
| 조리 시간 | 사용 가능한 조리시간 |
| 원하는 맛 | 매콤, 담백 등 |
| 함께 마실 술 | 식사와 함께할 술 |
| 보유 재료 | 현재 가지고 있는 식재료 |

일부 조건은 사용자가 선택적으로 입력할 수 있도록 구성하였다.

## 7. AI 추천 결과

AI는 **정확히 3개의 PICK**을 반환하도록 설계하였다.

각 PICK에는 다음 정보가 포함된다.

- 한 상의 제목
- 최소 3개의 메뉴
- 술 궁합
- 조리 난이도
- 맛 특징
- 추천 이유

또한 세 PICK이 지나치게 비슷하지 않도록 프롬프트에서 서로 다른 스타일의 식사를 추천하도록 지시한다.

## 8. AI 응답 데이터 구조

프론트엔드에서 AI 결과를 안정적으로 처리할 수 있도록 JSON 구조를 사용한다.

```json
{
  "picks": [
    {
      "title": "매콤한 집밥 한 상",
      "menus": [
        "제육볶음",
        "된장찌개",
        "계란말이"
      ],
      "alcohol_match": "★★★★☆",
      "difficulty": "보통",
      "taste": "매콤 · 구수 · 담백",
      "reason": "서로 잘 어울리는 집밥 메뉴 구성입니다."
    }
  ]
}
```

백엔드에서는 AI 응답을 JSON으로 변환한 후 형식이 올바른지 검사한다.

## 9. 서비스 처리 흐름

전체 서비스는 다음 순서로 동작한다.

```text
사용자
   ↓
식사 조건 입력
   ↓
HTML 입력폼
   ↓
JavaScript
   ↓
fetch()
   ↓
POST /api/recommend
   ↓
Python FastAPI
   ↓
Codyssey AI API
   ↓
gpt-5-mini
   ↓
JSON 추천 결과
   ↓
FastAPI 응답 검증
   ↓
JavaScript
   ↓

```

이 구조를 통해 브라우저가 외부 AI API를 직접 호출하지 않도록 하였다.

## 10. 레시피 검색 기능

AI 추천 결과에서 각 음식 옆에 **레시피 검색 버튼**을 제공한다.

예:

```text
🍴 제육볶음       🔍 레시피 검색
🍴 된장찌개       🔍 레시피 검색
🍴 계란말이       🔍 레시피 검색
```

사용자가 버튼을 누르면 해당 메뉴명에 `레시피`라는 검색어를 결합하여 검색 페이지를 새 창으로 연다.

예:

```text
제육볶음 + 레시피
```

별도의 레시피 API를 사용하지 않고 검색 링크를 동적으로 생성하는 방식으로 구현하였다.

## 13. API Key 보안

AI API Key는 코드에 직접 입력하지 않고 환경변수를 사용한다.

환경변수명:

```text
CODYSSEY_API_KEY
```

Python에서는 다음과 같은 방식으로 환경변수를 읽는다.

```python
api_key = os.getenv("CODYSSEY_API_KEY")
```

배포 환경에서는 Vercel의 Environment Variables에 API Key를 등록한다.

이를 통해 HTML이나 JavaScript를 확인하더라도 실제 API Key가 노출되지 않도록 하였다.

## 15. 로딩 처리

AI API는 응답 생성에 시간이 필요할 수 있다.

따라서 추천 요청 후 결과가 도착할 때까지 사용자에게 로딩 상태를 표시하도록 구현하였다.

## 19. 개발 과정에서 해결한 주요 문제

### 19.1 AI API 연동

AI 요청을 브라우저에서 직접 처리하지 않고 Python FastAPI 백엔드를 통해 처리하도록 구성하였다.

이를 통해 API Key를 프론트엔드에서 분리하였다.

### 19.2 Vercel Python 의존성 오류

배포 후 다음과 같은 서버 함수 오류가 발생하였다.

```text
FUNCTION_INVOCATION_FAILED
```

원인을 확인한 결과 Python 코드에서 사용하는 `httpx`가 배포 환경의 의존성에 포함되지 않은 것이 문제였다.

`pyproject.toml`에 필요한 의존성을 명시하여 해결하였다.

```toml
dependencies = [
    "fastapi>=0.141.1",
    "httpx>=0.27.0"
]
```

### 19.3 HOME 페이지 라우팅 오류

메뉴 추천 페이지에서 HOME으로 이동할 때 다음 오류가 발생하였다.

```json
{
  "detail": "Not Found"
}
```

FastAPI에 `/index.html` 라우트를 추가하여 해결하였다.

### 19.4 ABOUT 페이지 문제

초기 `about.html` 파일이 비어 있어 ABOUT 메뉴를 선택해도 콘텐츠가 표시되지 않았다.

ABOUT 페이지 콘텐츠를 작성하여 해결하였다.

### 19.5 한글 인코딩 문제

ABOUT 페이지 작성 과정에서 한글이 깨져 표시되는 문제가 발생하였다.

파일 내용을 UTF-8 형식으로 다시 작성하고 저장하여 정상적으로 표시되도록 해결하였다.

```text
기획
 ↓
```
