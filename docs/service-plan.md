「오늘 뭐 먹지 AI」 서비스 기획서

1. 서비스 개요

서비스명

오늘 뭐 먹지 AI

한 줄 소개

메뉴 하나가 아니라, 오늘 먹고 싶은 한 상을 골라드립니다.

서비스 목적

매일 반복되는 "오늘 뭐 먹지?"라는 고민을 AI를 활용하여 해결하는 웹서비스이다.

기존의 단순 메뉴 추천 방식에서 벗어나 사용자가 누구와 식사하는지, 어떤 분위기의 식사를 원하는지, 조리 가능한 시간, 원하는 맛, 함께 마실 술, 보유 재료 등을 입력하면 AI가 해당 조건을 종합적으로 분석한다.

그 결과 음식 하나만 추천하는 것이 아니라 실제 한 끼 식사로 함께 먹기 좋은 메뉴를 조합하여 3가지 '한 상 차림'으로 제안한다.

2. 문제 정의

식사 메뉴를 정할 때 사람들은 단순히 음식 종류만 고려하지 않는다.

예를 들어 같은 저녁 식사라도 다음과 같은 조건에 따라 적합한 메뉴가 달라질 수 있다.

혼자 먹는 식사

가족과 함께하는 식사

친구와 술을 곁들이는 식사

빠르게 준비해야 하는 식사

매운 음식이 먹고 싶은 날

냉장고에 있는 재료를 활용하고 싶은 경우

따라서 단순 랜덤 메뉴 추천보다는 여러 조건을 함께 고려하는 맞춤형 추천이 필요하다고 판단하였다.

현재 가지고 있는 재료를 활용할 수 있는 메뉴 아이디어가 필요한 사용자

4. 핵심 차별점

일반적인 메뉴 추천 서비스가 음식 하나를 추천하는 방식이라면, 오늘 뭐 먹지 AI는 '한 상 차림'을 추천한다.

예를 들어 단순히 "제육볶음" 하나를 추천하는 것이 아니라,

제육볶음

김치찌개

상추겉절이

처럼 함께 먹기 좋은 메뉴를 조합하여 실제 식사에 가까운 형태로 추천한다.

또한 한 번의 요청에서 서로 다른 스타일의 PICK 3개를 제공하여 사용자가 최종 선택할 수 있도록 한다.

6. AI 기능

AI의 역할

AI는 사용자가 입력한 여러 식사 조건을 분석하여 서로 다른 스타일의 한 상 차림 3개를 생성한다.

AI 입력 데이터

AI에게 전달되는 주요 정보는 다음과 같다.

people: 함께 먹는 사람

situation: 식사 상황

food_type: 선호 음식 종류

cook_time: 가능한 조리 시간

taste: 원하는 맛

alcohol: 함께 마실 술

ingredients: 보유 재료

AI는 정확히 3개의 PICK을 생성한다.

각 PICK에는 다음 정보가 포함된다.

한 상 이름

최소 3개의 메뉴

술 궁합

조리 부담

추천 이유

10. 프론트엔드와 백엔드 분리

AI API Key를 브라우저 JavaScript에 직접 작성하지 않았다.

프론트엔드에서는 /api/recommend만 호출하고 실제 AI API 호출은 Python 백엔드에서 수행한다.

이를 통해 사용자가 브라우저에서 API Key를 직접 확인할 수 없도록 구성하였다.

11. 환경변수 관리

AI API Key는 코드에 직접 입력하지 않고 다음 환경변수로 관리한다.

CODYSSEY_API_KEY

로컬 개발환경에서는 PowerShell 환경변수로 설정하고, 실제 배포환경에서는 Vercel의 Production Secret 환경변수로 관리한다.

GitHub 저장소에는 실제 API Key를 저장하지 않는다.

12. 오류 처리

웹서비스 사용 중 발생할 수 있는 상황을 고려하여 다음 오류 처리를 구현하였다.

필수 입력 누락: 필수 항목이 선택되지 않은 경우 AI API를 호출하지 않고 사용자에게 입력 안내 메시지를 표시한다.

Loading 상태: AI가 추천을 생성하는 동안 "추천 중..." 상태를 표시한다.

API 호출 오류: AI 서비스 호출이나 서버 통신 과정에서 오류가 발생하면 다시 시도할 수 있도록 안내한다.

Timeout: AI 응답 시간이 일정 시간을 초과하면 Timeout으로 처리한다.

AI 응답 형식 오류: AI가 정상적인 JSON을 생성하지 못한 경우 서버에서 오류로 처리한다.

추천 개수 검증: AI가 정확히 3개의 PICK을 생성했는지 확인한다.

메뉴 개수 검증: 각 PICK에 최소 3개의 메뉴가 포함되었는지 확인한다.

13. 반응형 웹

PC뿐 아니라 스마트폰에서도 서비스를 사용할 수 있도록 반응형 CSS를 적용하였다.

14. 구현 과정에서 발생한 문제와 해결

문제 1. Vercel Python Serverless Function 오류

배포 과정에서 다음 오류가 발생하였다.

500 INTERNAL_SERVER_ERROR
FUNCTION_INVOCATION_FAILED

원인

로컬 Python 가상환경에는 httpx가 설치되어 있었지만 Vercel이 사용하는 프로젝트 의존성 설정에는 httpx가 포함되어 있지 않았다.

따라서 로컬에서는 정상적으로 실행되었지만 Vercel Serverless 환경에서는 Python 함수가 실행되지 않았다.

해결

pyproject.toml의 dependencies에 다음 패키지를 추가하였다.

dependencies = [
    "fastapi>=0.141.1",
    "httpx>=0.27.0"
]

수정 후 Production 환경에 다시 배포하여 정상 작동을 확인하였다.

배운 점

로컬에서 설치한 Python 패키지가 자동으로 배포 서버에도 설치되는 것은 아니며, 배포환경에서 필요한 의존성을 프로젝트 설정 파일에 정확히 명시해야 한다는 점을 학습하였다.

18. 기대 효과

사용자는 여러 음식 사이트를 검색하거나 메뉴를 하나씩 고민할 필요 없이 자신의 현재 상황과 취향을 입력하는 것만으로 AI에게 실제 식사에 활용할 수 있는 메뉴 조합을 추천받을 수 있다.

또한 이 프로젝트는 단순 정적 웹페이지가 아니라 사용자 입력, 프론트엔드와 백엔드 통신, 외부 AI API 호출, 구조화된 데이터 처리, 오류 처리, 환경변수 관리 및 실제 웹 배포까지 하나의 서비스 흐름으로 구현한 프로젝트라는 점에 의미가 있다.
